# Core features audit against Alex's seven authoritative features

Audit date: 2026-10-27. Baseline: `7e05d521c2a2f9add46423e39a4b27d6e67049e3` (`origin/main` when this worktree was dispatched). This is a source-and-document audit, not a runtime certification. Recommendations and classifications below are product judgments inferred from the cited evidence. No application code, configuration, tests, CI, credentials, installed app, gateway, VM, or other worktree was changed or inspected for private state.

## Decision

Alex's updated seven-feature list supersedes the earlier four-pillar framing. **All seven are core product commitments:** a simple workspace; fast, accurate local-Mac and workspace-browser computer use; lid-close browser handoff; a live VM desktop window; the same threads on every device; added tools on stock production agents; and proactivity. Simplicity remains a design constraint across them, not a reason to demote computer use or the VM view. The implementation has meaningful pieces of each, but existing source/fixture evidence does not certify the complete promises. [desktop/README.md:3–21](../../desktop/README.md#L3-L21), [desktop/README.md:59–65](../../desktop/README.md#L59-L65), [docs/continuity.md:3–29](../continuity.md#L3-L29).

**Hermes and Grok Bot are the targets. Claude Duet is conditional on production availability, a supported connector and live acceptance.** Codex is the computer-use quality benchmark, not a target agent. Claude Code and Codex integrations are out of the current roadmap; if justified later, use only a thin CLI wrapper over Tailscale. This is Alex's product direction; current Grok/Duet transport, approval and image limits remain **UNVERIFIED** by this audit and belong to the parallel compatibility report. [desktop/docs/remote-agents.md:14–22](../../desktop/docs/remote-agents.md#L14-L22), [compatibility draft PR #151, report:14–26,98–108](https://github.com/capthvnsen/alans-way-agents/blob/a53d45ce3aa9abb289484a96b1780793eaa90298/docs/research/agent-compat-matrix.md#L14-L108).

**Confirm Tailscale as the private backbone; challenge “everything already uses it.”** Host/VM SSH and tool routing are designed around the tailnet, but loopback IPC, Telegram delivery, provider APIs and optional HTTPS voice/hosted-client ingress are distinct legs. Never expose desktop loopback API/CDP to make a hosted connector reachable. A public TLS front would be a deliberate exception, not evidence of end-to-end private Tailscale transport. The concrete topology decision is below. [README.md:17](../../README.md#L17), [SECURITY.md:11–30](../../SECURITY.md#L11-L30), [desktop/docs/remote-agents.md:37–48](../../desktop/docs/remote-agents.md#L37-L48), [mobile/README.md:26–28](../../mobile/README.md#L26-L28).

## Method and classification

Alex supplied these authoritative criteria in the updated task; they are requirements, not claims of implemented behavior:

| ID | Authoritative core feature | Product acceptance meaning |
| --- | --- | --- |
| **F1** | Workspace: very simple left-side chat and a browser that feels like ChatGPT desktop's built-in browser. | One obvious conversation/browser journey; competitor-level experience remains an acceptance target, not a result inferred from matching layout. |
| **F2** | Codex-level MCP/CUA on Alex's local Mac **and specifically inside the workspace browser**, extremely fast and accurate with remote agents. | Both native-app and workspace-tab task completion, observed through the real remote path; no substitution of generic VM control for local/browser control. |
| **F3** | Browser work hands off to the VM when the laptop lid closes. | Fresh target identity, explicit reconstruction limits, no duplicated uncertain action, truthful return-to-laptop behavior. |
| **F4** | Live window into the VM's desktop. | Correct VM identity, live connected state and recovery; this is core, even if the overlay can be hidden. |
| **F5** | Same threads on any device through Telegram or the agent's own app, e.g. Grok Bot. | The agent's authoritative thread remains the thread across devices; tool access alone does not synchronize transcripts. |
| **F6** | Each target agent's main production version, purely through added tools; never fork agents. | Stock Hermes and stock Grok Bot, conditional Duet; public tool/plugin/configuration seams and versioned acceptance. |
| **F7** | Proactivity. | Useful bounded initiative in the authoritative agent thread with user-controlled frequency, quiet time and consequential-action consent. |

**S** denotes the cross-cutting simplicity constraint. Trust, safety and user control are mandatory acceptance constraints across F1–F7; they do not replace or silently add to Alex's seven. Classifications measure each feature against this updated list.

**Core** directly delivers an authoritative feature or protects its essential user boundary. **Supporting** makes a core workflow usable, recoverable, or distributable. **Cut/merge candidate** adds another product surface or duplicates a path without being necessary for the seven-feature promise; it is a recommendation for review, not authorization to delete it. A capability can be core while its present implementation needs consolidation.

**Code** means an implementation path was inspected. **Docs/external** means this repository describes behavior owned elsewhere; actual deployed behavior is **UNVERIFIED**. **Research/planned** means the cited source explicitly describes an experiment or future contract. All live product acceptance, physical lid-close behavior, provider performance, signed distribution, device behavior, and external service availability remain **UNVERIFIED** unless expressly stated otherwise. Existing tests are evidence of intended checks, not tests run by this audit; the repository itself distinguishes fixtures from authenticated remote proof. [docs/compatibility.md:70–76](../compatibility.md#L70-L76), [docs/quality/README.md:9–29](../quality/README.md#L9-L29).

Inventory granularity is a user capability or independently meaningful trust/operating boundary. Individual action verbs, parser branches, test cases, build helpers, and repeated platform adapters are grouped under their owning feature. The existing experience checklist includes both parent areas and narrower checks, so counting its rows as distinct product features would double count. [docs/quality/README.md:31–34](../quality/README.md#L31-L34).

## Tailscale: confirm the backbone, identify the exceptions

**Confirm:** use Tailscale for private desktop↔VM/server links, SSH stdio/tool forwarding and private VM viewing, with normal SSH host-key checking. Keep the desktop API and Chromium debugger on loopback; they are reached by the trusted local connector, not opened to the tailnet. Tailscale protects connectivity, not per-bot authorization, request-bound approval or shared browser-account isolation. [README.md:17–26](../../README.md#L17-L26), [SECURITY.md:11–30](../../SECURITY.md#L11-L30), [desktop/docs/integration.md:108–127](../../desktop/docs/integration.md#L108-L127).

**Challenge the literal “everything” claim:** Telegram messages and model/speech provider traffic are external service calls, and current voice deployment permits a public HTTPS front. These application protocols need not be replaced with SSH to keep Tailscale as the infrastructure backbone. A phone can reach a private viewer with Tailscale, but that does not prove the Telegram Mini App can reach every private endpoint. [README.md:72–77](../../README.md#L72-L77), [ios/README.md:67](../../ios/README.md#L67), [mobile/README.md:26–28](../../mobile/README.md#L26-L28), [docs/mobile-ios-plan.md:104–110](../mobile-ios-plan.md#L104-L110).

**Resolve the hosted-agent leg before promising Grok:** the repo records an Oct 26 observation that outbound SSH was blocked, and documents HTTPS proxy ingress as fallback. The compatibility draft likewise treats hosted-client transport/auth/images/elicitation as partly unverified. **UNVERIFIED:** whether production Grok Bot's computer can join Alex's tailnet or reach a private service, and whether a production Duet connector can. Do not assert that Tailscale enrollment is possible merely because the client has a cloud computer. [desktop/docs/remote-agents.md:14–22](../../desktop/docs/remote-agents.md#L14-L22), [desktop/docs/remote-agents.md:37–48](../../desktop/docs/remote-agents.md#L37-L48), [compatibility draft report:14–26](https://github.com/capthvnsen/alans-way-agents/blob/a53d45ce3aa9abb289484a96b1780793eaa90298/docs/research/agent-compat-matrix.md#L14-L26).

Recommendation: prefer a tailnet-connected agent runtime or supported tailnet-access connector. If production Grok cannot do that, Alex must choose between a **narrow explicitly approved authenticated HTTPS ingress exception backed by Tailscale internally**, and deferring Grok support. Keep per-agent revocable credentials, exact bot mapping and action-bound approvals regardless; never expose desktop loopback/CDP or relax approval to satisfy a transport. This is a proposed decision, not a claim that either deployment was validated. [SECURITY.md:11](../../SECURITY.md#L11), [desktop/docs/remote-agents.md:48–65](../../desktop/docs/remote-agents.md#L48-L65), [compatibility draft report:102–108](https://github.com/capthvnsen/alans-way-agents/blob/a53d45ce3aa9abb289484a96b1780793eaa90298/docs/research/agent-compat-matrix.md#L102-L108).

## Is another pillar missing?

The seven already include computer use, live VM visibility, thread continuity and stock multi-agent reach, which were under-specified in the earlier four. **Trust and user control are still missing as an explicit acceptance axis, but I recommend a cross-cutting gate rather than an eighth feature.** Browser commits, local desktop permission and agent-native consent grant different scopes; known bots bypass the local desktop dialog, and the HTTP bridge cannot carry browser elicitation. Every core flow needs visible machine/agent identity, revocable permission, human handback and truthful uncertainty. Do not imply the existing app is a hostile-agent sandbox. [desktop/docs/remote-agents.md:19–20](../../desktop/docs/remote-agents.md#L19-L20), [desktop/docs/remote-agents.md:50–65](../../desktop/docs/remote-agents.md#L50-L65), [desktop/docs/integration.md:108–127](../../desktop/docs/integration.md#L108-L127).

Do not add a separate fleet-orchestration pillar. Supporting both Hermes and Grok is core under F6; adding more specialist agents, per-bot desktops or a new scheduler is a different expansion, and the current browser sign-ins and VM desktop are shared. Likewise, voice is an optional access method for F5, not a substitute for proving thread identity. [docs/agent-setup.md:3–29](../agent-setup.md#L3-L29), [desktop/docs/integration.md:248–254](../../desktop/docs/integration.md#L248-L254), [ios/README.md:55–69](../../ios/README.md#L55-L69).
