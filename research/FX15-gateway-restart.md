Research pins (2026-10-15): Hermes [`d923a5eb487a17c0a68801bba9ef0f56c81040a8`](https://github.com/NousResearch/hermes-agent/tree/d923a5eb487a17c0a68801bba9ef0f56c81040a8); plugin [`a8f48de36830e7f11c46ca9884e28e7b4361d819`](https://github.com/capthvnsen/alans-way-agents/tree/a8f48de36830e7f11c46ca9884e28e7b4361d819). ## Decision

A gateway restart remains necessary for the complete setup choices. Plugin hot reload alone does not apply the managed browser MCP configuration, Telegram adapter settings, or the startup snapshot of busy-input policy. The supported general lifecycle route is **outside the gateway**, e.g. the app's existing SSH connection. A human's incoming `/restart` is supported and drains current work, but is not an agent terminal API. Do not treat an outgoing bot message containing `/restart` as execution.

**Removing `--restart` alone does not fix the supplied setup script.** The terminal guard recursively scans referenced script source; it does not evaluate shell flags/control flow. The exact scanner returns `(True, None)` for `sh /tmp/next-FX15-plugin-source/setup.sh --skip-plugin --non-interactive`, with no restart flag. The source still contains gateway drain-stop/replay and restart functions, plus macOS `launchctl bootstrap`; that verb is explicitly refused regardless of its job label. A genuinely bot-safe entrypoint must own no gateway lifecycle behavior and no forbidden service maintenance. Moving an unused restart function while retaining other such operations is insufficient. The smallest robust alternative is to run setup itself as well as the final restart from the app's external SSH process.

## Sanctioned restart and authorization

Incoming `/restart` is handled by [`gateway/slash_commands.py:529`](https://github.com/NousResearch/hermes-agent/blob/d923a5eb487a17c0a68801bba9ef0f56c81040a8/gateway/slash_commands.py#L529). It saves notification/dedup markers, determines service/container ownership, and calls `request_restart`. That method refuses new turns while allowing active turns to finish, waits for drain, then stops/relaunches ([`gateway/run_shutdown.py:1691`](https://github.com/NousResearch/hermes-agent/blob/d923a5eb487a17c0a68801bba9ef0f56c81040a8/gateway/run_shutdown.py#L1691)).

The incoming user must already pass platform admission; slash access then applies. When no `allow_admin_from` scope list is configured, existing admitted users retain slash access. When it is configured, `/restart` requires an admin ID or explicit `user_allowed_commands` permission; only `help` and `whoami` form the unconditional non-admin floor. See [`gateway/slash_access.py:1`](https://github.com/NousResearch/hermes-agent/blob/d923a5eb487a17c0a68801bba9ef0f56c81040a8/gateway/slash_access.py#L1), [`gateway/run_inbound.py:839`](https://github.com/NousResearch/hermes-agent/blob/d923a5eb487a17c0a68801bba9ef0f56c81040a8/gateway/run_inbound.py#L839), [`gateway/run_busy.py:1117`](https://github.com/NousResearch/hermes-agent/blob/d923a5eb487a17c0a68801bba9ef0f56c81040a8/gateway/run_busy.py#L1117). Do not relax those lists for setup.

No generic model-facing self-restart tool or deferred restart verb was established in this pin. The local control socket has `pause-for-update`, but its source explicitly delegates relaunch responsibility to the external updater/service manager; it is not a sanctioned substitute for a bot restart tool. Registered mutation verbs are visible at [`gateway/run.py:5603`](https://github.com/NousResearch/hermes-agent/blob/d923a5eb487a17c0a68801bba9ef0f56c81040a8/gateway/run.py#L5603). Scheduling a cron restart is expressly refused ([`cron/lifecycle_guard.py:1`](https://github.com/NousResearch/hermes-agent/blob/d923a5eb487a17c0a68801bba9ef0f56c81040a8/cron/lifecycle_guard.py#L1)). The gateway CLI independently refuses inside-gateway lifecycle commands, beyond the terminal guard ([`hermes_cli/gateway.py:5062`](https://github.com/NousResearch/hermes-agent/blob/d923a5eb487a17c0a68801bba9ef0f56c81040a8/hermes_cli/gateway.py#L5062)).
